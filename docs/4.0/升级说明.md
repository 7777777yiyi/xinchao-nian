# 从 3.3 升级到 4.0

> 【4.0 草稿】10 月 5 日随 4.0 代码一起发布，发布前按最终代码再核对一遍。

4.0 是大版本：驱力的名单变了，存档格式升了一版，网页读的快照也多了新字段。**升级会自动迁移存档，但一定先备份。**

---

## 4.0 变了什么

**驱力：12 股 → 11 股**

| 3.3 | 4.0 | 说明 |
|---|---|---|
| `possess` 想她、占有 | `possess` | 「馋她」并进来了 |
| `crave` 馋她 | —— | 并进 `possess`，两股一直同涨同落 |
| `share` 想分享 | `share` 分享欲 | 「社交」并进来了，含义改成「有话想说」 |
| `social` 想聊天 | —— | 并进 `share` |
| —— | `favored` 偏爱 | **新增**：想被在乎、被回应、被选择。吃醋、被晾着、被忘记会让它涨 |
| 其余 9 股 | 不变 | `monitor` `libido` `curiosity` `boredom` `duty` `reflection` `grieve` `anger` |

**新的几层**

- **共情**：为对方的事心疼、替人不平、为自己的疏忽自责。按亲疏分档，越亲的人分量越重。
- **两层情绪**：底子（平静、安心、低落……）+ 起因（心动、害羞、吃醋……）。给人看的是起因那个词。情绪有惯性，不会一句话就翻过去。
- **慢变底色**：安全感、自信、心境。几天才变一点，网页上是花蕊。
- **情绪浮标**：有起因的情绪亮过的时刻，网页上漂在潮汐带上。
- **矛盾**：两股方向相反的劲儿拧在一起时（比如气着又舍不得）。
- **互动判断规则搬进心潮本体**：什么算吃醋、什么算心疼，以前要靠外面的前端自己判断，现在心潮自己带了一份。**这份规则是参考值**，见 [按你们自己的情况调](按自己情况调.md)。
- **小屋**：AI 能看到自己写过的信；未读来信一直提示，不再只提示 24 小时；上锁信一直提示还在。

## 升级步骤

### 1. 备份存档

```bash
docker run --rm -v xinchao-nian_xinchao-state:/s -v "$PWD":/b alpine \
  sh -c 'cp /s/state.json /b/state-备份.json; cp /s/cabin.json /b/cabin-备份.json 2>/dev/null; true'
```

卷名以 `docker volume ls` 里看到的为准。

### 2. 拉代码、重建

```bash
git pull
git submodule update --init
docker compose up -d --build
```

### 3. 确认版本和迁移

```bash
curl http://127.0.0.1:18110/health   # 版本号是 4.0.x
```

第一次结算时，存档会自动迁移：`crave` 并进 `possess`、`social` 并进 `share`（都取两者里较大的值），新增的 `favored` 从 0 开始。不需要手动改存档。

> 如果升级后马上调 `/v1/now` 报驱力超出范围，手动结算一次：`POST /v1/settle`（带服务令牌），之后就正常了。

### 4. 重新读手册

让 AI 读一遍新版《小机手册》。驱力名单变了，AI 记忆里的旧名字（馋她、社交）要对上新的。

### 5. 网页

平台网页已经按 4.0 改版。心潮升级后，花蕊、潮汐带、浮标会自动出现；没升级的，这几块显示灰色示例。字段格式见 [快照字段](快照字段.md)。

### 6. 改成你们自己的

升级后先观察几天，再按 [按你们自己的情况调](按自己情况调.md) 和《小机手册》里「怎么把心潮改成你们自己的版本」那一章，一项一项调。

## 你如果改过 3.3 的代码

- 改过驱力名字或数值：4.0 的 `dimensions.js` 改动很多，建议对照着重新改一遍，不要直接合并。
- 外部传旧驱力名（`crave`、`social`）进来：4.0 会自动认成新名字，不会报错。
- 自己写过前端读快照：旧字段都还在，新字段见 [快照字段](快照字段.md)。

## 想退回 3.3

把第 1 步备份的 `state.json` 放回卷里，切回 3.3 的代码重建。4.0 期间产生的新状态（偏爱、底色、浮标）会丢掉。
